# GoshaCrash 3.10.2-rc39

Consolidated test build for ASUS RT-AC68U and ZenWiFi BT10.

Key rc39 changes:
- existing config migration strips old whole-line comments before any YAML rewrite; YAML data is preserved byte-for-byte except GoshaCrash-owned fields;
- canonical Russian comments are regenerated after migration in UTF-8 without BOM;
- config-related AWK passes in installer/controller use LC_ALL=C so Cyrillic bytes are never locale-transcoded by ASUS BusyBox;
- fresh config is written directly as the final UTF-8 Russian-commented DIRECT placeholder in one heredoc; no data-first/decorate pass is used for a clean install;
- no comments-free fallback: final config with Cyrillic comments must pass real `mihomo -t`;
- rollback remains volatile under /tmp only; no persistent backup directory/file is created.

Retained rc34 changes:
- full audit of config.yaml generation/migration; fresh auto/manual configs are generated directly with canonical TUN/DNS blocks instead of post-patching a just-created file;
- modern auto config: stack=system, tun.enable=true, device=tun0, auto-route/auto-redirect/auto-detect-interface=true, dns-hijack present, no routing-mark;
- manual config: auto-route/auto-redirect/auto-detect-interface=false and routing-mark=9012; legacy ARMv5 uses stack=gvisor;
- base router config adds find-process-mode: off per Mihomo router guidance;
- existing configs preserve proxies/proxy-groups/rules/custom resolver lists while GoshaCrash-owned TUN/DNS/API/UI fields are normalized;
- if tun:/dns: are entirely absent, complete minimal sections are appended (Fake-IP/resolver defaults included for a missing DNS block);
- existing external-controller is normalized to 0.0.0.0:9090; external-ui/ui URL are normalized to Zashboard; missing/empty/CHANGE_ME secret gets a generated local secret;
- duplicate top-level tun:/dns: and flow-style tun: {...}/dns: {...} are rejected before mutation instead of creating ambiguous duplicate YAML;
- config migration is transactional: original user config is kept only in /tmp until the new Mihomo accepts it; installer abort restores it, and no persistent backup directory/file is created;
- required_config now validates expected tun.stack, dns-hijack presence and auto-detect-interface in addition to enable/device/routing/DNS;
- runtime routing rewrite creates missing tun:/dns: block sections and reasserts enable/device/listen fields before changing mode;
- removed ROUTING: AUTO/MANUAL from the interactive menu header; routing remains available in status/doctor/CLI;
- doctor distinguishes kernel /dev/net/tun from Mihomo-created tun0 and reports routing N/A when tun0 is down;
- installer no longer erases boot/watchdog/coldboot/controller logs during upgrade.

Previous consolidated fixes retained:
- menu header uses MIHOMO: and TUN: labels; PROFILE MODERN is removed;
- all menu rows are fixed to 45 visible columns; incremental arrow repaint is retained;
- Edit config and Restart are fully separated: edit validates with Mihomo -t and never restarts;
- invalid edits are not kept: the previous valid config is restored from a volatile /tmp copy;
- generated config.yaml is UTF-8 without BOM with Russian comments;
- nano is launched with a scoped UTF-8 locale and the scoped Optware runtime library path;
- persistent /jffs/addons/goshacrash is removed; runtime data/logs stay under the USB GoshaCrash directory;
- standard ASUS /jffs/scripts hooks remain because firmware calls them;
- modern Mihomo remains pinned to v1.19.30 with ELF architecture guard;
- cold-boot boot-ID lock/watchdog hardening from rc25/rc26 is retained;
- rulesets/ and proxies/ are not created; old empty copies are removed with rmdir only.
